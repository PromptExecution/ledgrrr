<architecture>
Use one local SQLite database through exact rusqlite =0.33.0 with bundled SQLite, existing serde/serde_json/thiserror/tempfile workspace libraries, and canonical ufo-types. This version is cached locally. Keep the library synchronous and provider-neutral; async hosts can isolate blocking I/O. Credentials, authenticated ActorId construction and provider network access remain host/adapter responsibilities. The owner API treats its supplied authenticated actor as a trusted host boundary and never interprets a client-selected string as authentication.

Keep original source/attachment bytes and original submitted envelope bytes in immutable SHA-256-addressed BLOB rows in this same database. Preserve canonical bundle bytes separately when the input JSON formatting differs; raw-byte digest and canonical full-bundle digest are distinct identities. A transaction can therefore durably create artifacts, validate their references, insert the intent and return Pending together. No filesystem rename sidecar or custom journal is needed. Do not expose global digest lookup: retrieval always verifies project access and a project artifact reference.

Initialize schema only on an empty database under an immediate transaction. Use application_id, user_version and checked schema metadata; reject unrelated populated databases, unsupported versions and corrupt records. Supported future migrations must be explicit ordered transactions preserving receipts and byte hashes; never reset or guess. Verify foreign_keys=ON, journal_mode=WAL and synchronous=FULL and configure a bounded busy timeout on every connection. Restrict this deployment to local filesystems; a network filesystem and distributed authority are outside these storage guarantees. SQLite configuration and transactions follow official references: https://www.sqlite.org/pragma.html and https://www.sqlite.org/lang_transaction.html; rusqlite Connection/Transaction APIs: https://docs.rs/rusqlite/0.33.0/rusqlite/struct.Connection.html.

Schema responsibility: projects with immutable provider binding and explicit bootstrap owner; grants keyed by project/actor with read, propose and administer permissions; content-addressed immutable bytes and project references; operations uniquely keyed by (project, operation) with immutable branch/actor/expected_head/proposal_digest and generation-guarded canonical receipt; branch dispatch reservation with monotonic fence and dispatch evidence. Use named columns, constraints and foreign keys for identity/preconditions and canonical JSON for upstream values, then validate on deserialization. Provider binding identifies configured provider/project handles, not credentials. Reject branch/provider mismatch and bind bundle context project to the owner project. Branch context/proposal parent must agree with intake expected head; reject inconsistent base data rather than coercing it.

Persist dispatch-started evidence before any future provider request. For a backend without conditional writes, a local lease cannot fence an in-flight remote request. Never reclaim a dispatched reservation based solely on timeout or generation. Recovery must list its exact immutable intent and evidence for adapter reconciliation; Ambiguous keeps that reservation until an explicit matching remote proof or verified quiescence resolves it. This milestone supplies storage state only and must not claim it constrains every real provider route.
</architecture>
